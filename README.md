Темы для [UnicoreCMS] — каждая ставится папкой в `themes/`, править код CMS не нужно.

Тема — не цветовая схема, а слой вёрстки: она подменяет страницы ядра, добавляет свои компоненты
и меняет палитру. Светлая и тёмная схемы есть в самом ядре и от темы не зависят.

- Что меняет конкретная тема — в README внутри её папки
- Как устроен слой и что в нём можно подменить — в [документации]
- Собирать тему не нужно: она состоит из исходников и собирается вместе с фронтом

## Темы

| Тема | Сторона | Что показывает | Контракт |
| ------ | ------ | ------ | ------ |
| [Аврора] | Сайт | Своя палитра, своя главная, свой компонент и строки | `^1.0.0` |
| [Нуар] | Сайт | Вторая тема сайта: подменяет главную и страницу доната | `^1.0.0` |
| [Графит] | Панель | Preset PrimeVue и его палитра, подмена дашборда | `^1.3.0` |

Эти три темы — учебные: они показывают механику слоя, а не готовый внешний вид. Ставить их на
боевой сайт незачем, а вот как заготовку для своей — берите.

Контракт — диапазон версий `unicore-api`, с которыми тема работает. Тема с несовместимым контрактом
не подключится, причина будет видна на странице «Темы» в админке.

## Установка

Руками, в корне установки CMS:

```
1. Скопируйте папку темы в themes/       например themes/aurora
2. Выберите её на странице «Темы»        отдельно для сайта и для панели
3. pnpm run build:client                 или build:admin, смотря чью сторону меняли
```

Через админку: сложите папку темы в zip и нажмите «Установить из архива» на странице «Темы». CMS
распакует архив в `themes/<id>`, останется выбрать тему и пересобрать фронт.

Тем может лежать сколько угодно, активные хранятся в `themes/state.json` по сторонам. Переменные
`UNICORE_THEME` и `UNICORE_ADMIN_THEME` в `.env` жёстко фиксируют тему своей стороны и блокируют
выбор из админки — это для стендов и CI.

Строки темы лежат в её папке `locales/` с ключами `theme.<id>.`: при старте сервера они попадают
в общий словарь и правятся в редакторе локализации.

## Своя тема

```
themes/<id>/
  theme.json           манифест: side, componentPrefix, primevue, primevueTokens, tokens, pages
  nuxt.config.ts       регистрация компонентов и стилей темы
  assets/tokens.scss   своя вёрстка
  components/          компоненты с префиксом Theme
  pages/               свои страницы и подмена страниц ядра
  locales/{ru,en}.json строки темы
```

Что стоит знать до первой сборки:

- Палитра PrimeVue задаётся полем `primevueTokens` в манифесте, а не переменными `--p-*` в CSS:
  PrimeVue вставляет свои переменные скриптом позже любого файла стилей и файл темы их не перебьёт
- Компоненту темы нужен префикс из `componentPrefix`. Совпадение имени с компонентом PrimeVue или
  ядра перекрыло бы его во всём приложении, поэтому сборка падает с явной ошибкой
- Страницы ядра подменяются через `pages.replace`, убираются через `pages.remove`
- Подменённая страница отвечает и за то, что на ней рисовали модули: выводите `<ExtensionSlot />`
  с теми же именами слотов, иначе вставки модулей пропадут
